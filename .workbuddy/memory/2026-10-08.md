## 155.html 加功能：等差等势面 + 试探电荷初速度

## 155.html 二次返工（同作用域注入法）——修正上面第 28 行的做法

- **上面"追加明文补丁 script 就能访问 let/const"是错的**，那次改动虽然看着能用，实际补丁里所有函数体在**调用时**才解析标识符 → 补丁挂了。老师实测反馈两个硬故障：① 界面①里速度滑块拖了，粒子放下后还是 v=0；② 等势面开关点了，画面什么都没有。
- **根因**：加密块的 `let/const/function` 都在 `(0, window.eval)(decoded)` 的**间接 eval** 里声明——间接 eval 是**全局**作用域，但 `let/const` 只落在全局**词法环境**里，不挂 window；而function 声明虽挂 window，原脚本内部局部标识符名又冲突。独立 `<script>` 里的补丁看不到这些名字，全 undefined，而且不报错，静默失效。
- **根治手法（eval 桥接注入，原加密块一个字节未动）**：
  1. 在加密 script 之前插 `<script>window.__PATCH_155 = "<补丁源码 JSON 转义字符串>";</script>`；
  2. 再插一段桥接 `<script>`：`var real = window.eval; window.eval = function(src){ return real.call(undefined, src + (window.__PATCH_155 || '')); };`；
  3. 加密块里的 `(0, window.eval)(decoded)` 一跑，桥接就把**补丁源码拼到原源码末尾**再间接 eval → 两者处于同一全局作用域，补丁可直接写 `sourceCharges`、`testCharges`、`ctx`、`K`、`width`、`height`。
- 配套坑点：
  - `real.call(undefined, ...)` 而不是 `real(src)`：间接调用才走全局作用域，否则函数体里的 let/const 又是 undefined。
  - 文件是 **CRLF**，任何正则/字符串锚点都要写 `\r\n`，否则"未找到加密 script"。
  - `add-test` 的 click 用 `addEventListener` 追加（原 onclick 在 load 时才赋值，会覆盖补丁赋的值）。⚠️ **但别指望时序**：补丁监听器在「脚本解析时」注册，比 load 里赋的 `.onclick` 更早，所以点击时**补丁先跑、新粒子还没 push**——靠"listener 排在 onclick 后"是错的。正确做法是把落速逻辑放进原 onclick **内部同步调用**的函数（如 `renderTestControls`）里。
  - 等势面加 `nseg` 计数，一层都没画出来时画布底部提示"试着加大电荷量或减少层数"——原来无提示，老师只看到"开了没反应"。
- **验证升级**：vm 沙箱里 `sandbox.window = globalThis`、`vm.runInContext('var window = globalThis;')`、`sandbox.eval = vm.runInContext('eval', ctx)`（直接给 sandbox.eval 会导致 real.call 拿不到）、atob 用 Buffer 版 + Uint8Array + 手写 TextDecoder.decode、canvas 桩必须给 `offsetWidth/offsetHeight`（否则 width/height 是 NaN，网格全画不出来）。测试脚本里"语句"和"表达式"要分开：`stmt()` 跑 IIFE，`run()` 包 `(\"` 取值——全局 let 不挂 sandbox 对象，只能 runInContext 求值。
- 最终实测全绿：等势面关=0 段 / 开=1101 段 + 3 个标值，层间电势差 8.929；粒子 v₀=4 θ=90° → v=(0,4)，v₀=6 θ=0° → v=(6,0)；卡片追加滑块正常；等势面单帧 3.8ms。
- 补丁源码保留在 `.patch155.js`（可再改），用正则幂等回写进 155.html 的 `window.__PATCH_155` 行即可，桥接脚本不动。

## 155.html 第四轮：最内圈等势面不圆（marching squares 精度）
- **现象**：单正/负电荷时，最靠近电荷那圈等势面不是正圆，看着像多边形/波浪形。物理上单电荷等势面必然是正圆，问题出在数值提取。
- **根因（两个叠加，主因是 clamp）**：① 原代码 `if (v > Vcap) v = CL` 把 r<Rmin 的电势压成常数平台（CL=1.15*Vcap），而最内圈等值线 tv=Vcap 正好贴在这个平台边界上 → 格子边上的线性插值从「真实 1/r 曲线」退化成「常数平台→实值」的近似，交点系统偏移且随每个格子相对平台的位置抖动 → 顶点半径 sd=1.53px、极差 5.3px（线宽才 1.2px，肉眼当然看出不圆）。② 网格 step=13 太粗，最内圈只有 28 段折线。
- **修复**：① 去掉上界 clamp，只留 r<4→NaN 与 !isFinite 兜底；② step 13→6（段数 28→60），几何误差 sd 1.53→0.08px、极差 5.3→0.27px；③ 等势面是静态的 → 缓存到离屏 canvas（eqSig 签名 = 画布尺寸+层数+各电荷 x,y,q，变了才重算），每帧只 ctx.drawImage 一次（无 DPR 缩放：原脚本 width=canvas.offsetWidth，1:1），所以 step=6 也不掉帧（实测 rAF 间隔 开 62.4ms vs 关 61.0ms，只差 1.4ms）；④ 最内/最外一圈（n=±N）改画实线 + lineWidth 1.8，虚线看不清圆，实线一眼就是正圆。
- **验证新招（抓离屏画布）**：hook `CanvasRenderingContext2D.prototype.drawImage`，只记录第一个参数引用（**不调用原函数，免递归**），就能拿到补丁里的离屏等势层 canvas，再 getImageData 做极坐标分析（72 个角度格取 min r）→ 最内圈 72/72 全覆盖、半径均值 44.58、极差 1.89px（含 ±0.5px 像素量化）。比整页开/关 diff 干净得多。
- **注意**：dash 虚线会让角度采样出现空洞，测圆必须挑「实线层」；文字标签 alpha 0.95 与线 0.5 不同，用 alpha∈[100,220] 过滤可剔除文字。
- **Node 复刻法（定位根因最快）**：把 marching squares 原样搬到 Node（K=5000、画布 1250x625、圆心 0.35W/0.5H），只换 clamp / step 参数，直接统计等值线顶点的半径 sd 与极差 → 一眼看出哪个参数在作怪，比浏览器试错快得多。

## 155.html 第五轮：放入试探电荷前先调正负（q 面板）
- **需求**：老师想在「放入之前」就定好试探电荷的正负与大小（原来原脚本 add-test 硬编码 `q:1`，只能在放入后用单个粒子卡片改）。
- **UI**：控制面板第 3 节加「待放入电荷 q」滑块（-5~5 step 1，与原卡片滑块量程一致，因为原 `updateTestChargeQ` 用的是 `parseInt`）+ 三个快捷按钮「＋正电荷 / －负电荷 / 0」（希沃大屏点按钮比拖滑块顺手），选中按钮加 outline 高亮；预览光标按 q 正负取绿/紫并在圆里画 +/−。
- **踩坑 A（关键时序）**：原 add-test 的 onclick 是「先 push（q 硬编码 1、坐标 `Math.random()`）→ **再同步** `renderTestControls()`」。凡是「push 之后才补 q」的写法（包括在 renderTestControls 包装里先 `origRender()` 再改），**卡片显示的永远是旧值 q=1**（实测面板选 -1，卡片仍显示 1 μC）。正确写法：在包装里 **`origRender()` 之前**先把 `__initN..` 区间内未 `__seen` 的粒子的 `q = curQ()` 写进去。
- **踩坑 B（覆盖无效）**：想用 `addBtn.onclick = function(){...}` 彻底接管，结果无效——补丁是在「脚本解析期」通过 eval 执行的，而原脚本 `window.onload=init` 之后会重绑 onclick，把补丁的覆盖冲掉。结论：不要依赖给 onclick 属性赋值，走 `addEventListener`/包装既有函数。
- **探针失效的坑**：原 `animate()` 里是词法调用 `drawTestCharge(tc)` / `updateTestChargePhysics(tc)`，**不是** `window.xxx()`，所以 `window.drawTestCharge = ...` 这类覆盖对渲染循环无效（之前误以为是速度箭头像素，其实那是放置预览光标的青色）。验证粒子只能用「卡片文本 + 像素颜色统计」。
- **验证**：卡片 q 滑块 value 依次为 -1/+1/-5（面板设定即放入值）；真鼠标点画布（place-mode）→ q=-3 且位置滑块同步到 700,500；像素统计正电 325 绿 #4CAF50 / 负电 325 紫 #9C27B0；受力对比（源电荷 +5 在 437,312，粒子放 700,260）正电 Δ=(+5,−2)、负电 Δ=(−5,+2) 完全反向 ✓；等势面回归差分 134916 像素正常。
- **质心统计陷阱**：测粒子位移时若「待放置预览光标」开着且鼠标留在画布上，预览像素会混进质心（把 dy 带偏），测运动前必须关 `place-mode`（关 `show-path` 同理）。
