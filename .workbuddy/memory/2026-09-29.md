## 诊断：小球与半圆槽「一个动另一个不动 / 不守恒」的原因（用户问，未改代码）
- 用户观察：一个物体有很小水平速度时另一个没有水平速度，怀疑不守恒。
- 代码事实：`_calcForce` 里球↔槽水平力在三个分支都是严格牛顿第三定律对（`tf.x = -bf.x`：y<=0 径向分支 `bf.x=-spring*nx, tf.x=spring*nx`；上两分支 `tf.x=-K*(...)=-bf.x`）。`_physicsStep` 用半隐式欧拉：`ballVel.x += (bf.x/m)dt; trackVel.x += (tf.x/M)dt; 再更新位置`。无阻尼（`air` 命中在 base64 贴图、`damp` 仅 OrbitControls 相机阻尼）。
- 用 Python 原样复刻验证：总水平动量 P = m·v球 + M·v槽 全程恒为 0.00000（守恒）；且 v槽/v球 恒 = −m/M（默认 m=1,M=3 → −1/3）。
- 结论：**仿真里水平动量是守恒的，不是 bug**。用户看到「一个动另一个不动」是两个原因叠加：① 守恒的是**动量 m·v**，不是**速度**——只有 m=M 时速度才等大反向；m≠M 时质量大的那个速度小（默认 M=3m，槽速=球速的 1/3；若把槽质量设很大，反冲几乎为 0，看着像不动，但这恰恰正确）。② 悬浮标签用 toFixed(2)，球速很小时槽速被四舍五入成「0.00」，误以为没有水平速度。
- 附带：动量图里「总量」曲线是**写死 push y:0**（`momTotalData.push({x, y:0})`），不是实时算的，别拿它当守恒证据。
- 给用户的建议（待确认是否要改）：A. 加实时总动量 Pₓ 数字读数（应恒≈0）+ 动量图加实时 P 曲线；B. 标签精度提到 toFixed(3)；C. 默认质量比改成演示友好值（m=M 或 m=3,M=1）。

## 修复：小球不在半圆里时，两物体水平速度恒为0（commit `0d902e8`，仅 `小球与半圆槽.html`）
- 用户要求：小球不在半圆槽里时，两物体水平速度应恒为 0。
- 根因（真 bug）：`_calcForce` 的 `else if / else` 分支（即 `ballPos.y > 0`、小球在槽外/空中时）仍施加水平力 `bf.x = K*(trackPos.x ± R - ballPos.x)` 与 `tf.x = -K*(...)`，等于小球在空中还与槽有水平耦合，于是出槽后两者水平速度非零（且互相不守恒感）。
- 修复两处：① `_calcForce` 的"出槽"分支删掉水平力、只留重力 `bf.y = -m*G`（此时 `bf.x=0, tf.x=0`）；② `_physicsStep` 在更新位置前加 `if (ballPos.y > 0){ ballVel.x=0; trackVel.x=0 }`，即槽外两物体水平速度恒清零。`node --check` 通过。
- 入槽（ballPos.y<=0）时行为不变：径向弹簧约束 + 正常的球↔槽水平动量交换，守恒演示照旧。出槽后小球只受重力直落、槽静止，符合"不在半圆里水平速度=0"。
