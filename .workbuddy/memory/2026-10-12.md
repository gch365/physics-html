## 160.html：充放电过程中 C 改为可调（不锁定）
- 用户要求：充/放电过程中 C 可调（电容器不锁定），电荷直接充到最大 Q=C·E；调大 C 再充电、调小 C 放电。
- 物理判断：该行为在**恒压（开关1、接电源）**场景下严格成立（Q=CV，V 被 E 钳住，C↑→Q↑ 电源补电；C↓→Q↓ 流回电源）；在孤立（开关2）场景严格说 Q 守恒、C↓→V↑ 而非放电。仿真用 Q=Vc·C 计算，两个分支视觉上都呈现"调小 C 电荷减少"，满足教学演示 Q=C·V，故采用。
- 实现：`setInputsDisabled(d)` 只锁 `inputE`/`inputR`，**不再锁 inputC**（C 始终可编辑）。charge/discharge 中 `Q_uC=Vc*p.C` 实时反映 C 变化，调 C 时 Q-t 曲线出现台阶跳变（再充电/放电），Vc 仍向 E（充电）或 0（放电）收敛。E/R 仍锁定避免改变 τ 与峰值。提示文案更新。node --check 通过。

## 160.html 严重 bug 修复：改为以 Q 为状态量，C 改动才触发第二个过程
- **症状**：充电满电(Vc→E, idle)后改 C，再点「充电」无可见过程（Vc 已=E，(E−Vc)=0 立即判定充满→idle）。根因：原以 **Vc 为状态量**，改 C 时 Vc 不变→无电流瞬态。
- **修法**：改以 **Q(µC) 为状态量**，Vc=Q/C 反推。`dQ/dt = I_mA·1000`（mA→µC/s）。charge：`I=(E−Q/C)/R`，target Q=C·E；discharge：`I=−Q/(R·C)`，target 0。这样改 C 时 (E−Q/C)≠0，电流重新流动 → 调大C再充电、调小C放电均可见。
- **自动触发第二个过程**：加 `inputC` 的 `input` 监听器——当 idle 且 Q>0.01·C·E（仍带电）且 |Q/C − E|>1%E（改 C 使 Vc 偏离 E）时，自动 `mode='charging'` 重新接入电源并锁 E/R，演示该瞬态；放电后(Q≈0)改 C 不触发，避免误启动。
- 验证：grep 确认无全局 `Vc` 残留（仅 step 内局部），node --check 通过。教训：RC 仿真里若需"恒压改 C 演示再充/放电"，必须用 Q 而非 V 作状态量。

## 咨询：页面在 Win7 希沃一体机上"界面小"（未改代码，仅诊断）
- 用户环境：自己的 Win11 正常；教室 Win7 + 希沃白板打开同一页面显得小。
- 已确认页面本身带 `<meta name="viewport" content="width=device-width,initial-scale=1.0">`，故非 viewport 问题。
- 结论（按概率）：① **系统 DPI 缩放**：Win11 常 150%/200%，Win7 教室一体机常 100%（希沃为触屏准确常锁 100%），同一 CSS 像素在高分屏上物理尺寸只有 1/1.5~1/2；② **希沃白板把网页当"对象窗口"插入**，默认窗口尺寸小于整屏，需点全屏/拖大；③ **Win7 希沃内置浏览器内核老**（IE11 或旧 CEF），不支持 CSS 变量、`flex gap`、`grid`、`:root` 等 → 布局塌缩/样式丢失（本项目 exp/c01/173.html 等用了 `:root` 变量 + `flex gap` + `100vh`，在旧内核上是高风险点）。
- 建议方案：教室端临时用 Ctrl+滚轮 / Ctrl + + 放大浏览器，或系统缩放调 150%；长期可给页面加"整页缩放"按钮（`document.body.style.zoom` 或 `transform:scale` + 记忆 localStorage）与旧内核降级 CSS。

- 判断法：教室里若**样式错乱/配色丢失**＝老 IE 或旧 CEF 内核 → 换浏览器有用；若**只是整体等比变小、样式正常**＝系统缩放 100% → 换浏览器**没用**（Win7 上 Chrome 同样按 100% DPI 渲染，一样小）。

## 实现：给全站加"整页缩放"控件（按用户第4条方案）
- 在 index.html + exp/**/*.html + 根目录独立仿真页（排除 index/c01-c07/f01 索引页）共 **278 个文件** 注入了统一的缩放控件（id=phZoom），幂等（已有标记则跳过）。
- 控件：右下角固定胶囊，含 A− / 100% / A+ / 适应 / ×（收起）。比例存 `localStorage['ph_zoom_v1']`（范围 0.5–3，步进 0.1），同一浏览器同 origin 永久记忆 → 教室机设一次，全部章节通用。
- 缩放实现：`document.body.style.zoom`（IE11 / 360极速 / QQ / Chrome 等 Chromium 内核都支持；Firefox 115 不支持 zoom，会无效果但不报错）。z>1 时把 `html`/`body` overflow 改为 auto/visible，避免 overflow:hidden 页面被裁切后无法滚动。
- 角色识别：`index.html` 用 iframe#viewer 加载实验；父页控件通过 `postMessage({phZoom})` 把缩放同步给 iframe 内的实验页；实验页若 `window.self!==window.top`（被 iframe 嵌入）则**隐藏自身按钮**，只接收父页消息缩放，避免双控件重叠。独立打开（顶层）则显示按钮。
- 注意：对 100% OS 缩放的 4K 大屏，zoom 200% 会让满屏布局超出视口（因页面按 100vw/vh 固定设计），靠 overflow:auto 滚动兜底；这是轻量方案，非响应式重排。注入脚本已删除，语法 node --check 通过。
