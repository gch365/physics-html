## 设计修正：3D_可变电容.html（用户 AI 审核反馈）
- 教训1：**电容不应放在回路正中央**——标准 RC 电路里电容是回路的一个元件（放左侧），开关在顶、电阻在右，组成干净矩形回路；不要把整个回路包在电容旋转轴外。
- 教训2：**放电时"电荷减少"必须肉眼可见**。仅用文字标签淡出不够。做法：在每片极板正面撒 ± 电荷小球（转子=黄球+、定子=青球−），子物体随极板转/移；放电时按 Vc/V₀ 比例逐颗 `visible=false` 让电荷"流走"。
- 教训3：电流粒子要明确是**电子 e⁻**，方向应为 负极板→外电路(经R)→正极板（与常规电流反向）。曲线顺序从定子节点起、绕到转子节点。
- 实现要点：电容整体包进 `capacitorGroup`(position x=-6)，极板/轴/电场/电荷小球/±Q标签/节点球均为其子物体；引线在世界系连接。

## 坑：单行长 data 替换会误删 featured 块
- 用 `re.search(r'const data = (\{.*?\});\s*const featured', ...)` 取数据块再切片替换时，整个匹配 span 包含 `const featured`，导致 `s[m.end():]` 起点在 featured 之后，**整段 featured 数组被丢掉**（data 本身写入正常）。
- 安全修法：用 `json.JSONDecoder().raw_decode(s, val_start)` 定位 data JSON 的精确结束索引 `end`；`tail=s[end:]` 即为 `;\n  = [featured...];\n  const names` 的残留，用 `= [`→`const featured = [` 恢复。重建后校验：`const featured` 存在、data 可被 json.loads、featured 9 项齐全。
- 教训：改 index.html data 时必须**只匹配 data 内部 JSON**，绝不把 `const featured` 拉进匹配 span；或全程用 raw_decode 定位边界。
